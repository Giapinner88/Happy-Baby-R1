# T005 — Jitter, loss and watchdog robustness

T005 is an executable bounded mapper/watchdog verification suite. Its six
atomic cases are declared in
[`config/r1_t005_watchdog_cases.json`](config/r1_t005_watchdog_cases.json):
jitter within timeout, packet drop below timeout, packet-loss watchdog timeout,
stale packet, deadman release and non-increasing sequence.

Each invalid path must emit exactly its declared hold reason, never dispatch
base velocity, and recover on the next valid command where declared. A mismatch,
missing evidence or malformed event is invalid; a hold mismatch is a valid
scientific failure. The execution backend is deterministic `R1TeleopMapper` +
`SimulationOnlyAdapter`, no Quest/Isaac/DDS/hardware channel.

```bash
python3 scripts/teleop/run_r1_t005_watchdog.py --case-id all
```

Each case writes immutable evidence under `runs/`. There is intentionally no
T005 video: this backend has no physics state or camera. T003-B remains the
physics/video evidence that the same deadman, timeout and sequence hold reasons
freeze targets in Isaac; T005 tests timestamp and packet behavior before that
sink.

## Initial outcome — 2026-08-11

The selected six-run matrix is recorded in
[`metadata/initial_selection.json`](metadata/initial_selection.json). All six
selected runs completed their declared mapper/adapter checks: no base-velocity
dispatch occurred; jitter and a 0.07 s received-packet age remained enabled;
the 0.60 s silence and 0.60 s stale packet both held with `command_timeout`;
deadman and duplicate sequence held with their respective reasons; every
declared recovery resumed upper-body dispatch. The earlier jitter run is kept as
an execution failure after a sink-event serialization error and is not selected.

This is valid bounded input-path evidence, with the stated no-physics/no-video
limitation. It neither extends the 30 mm/10° calibration screen nor proves
contact, collision or hardware safety.
